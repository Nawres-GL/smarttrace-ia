# SmartTrace RAG: Understanding the page, retrieval, LLMs and function roles

**Exact reference:** Phase 7 Hybrid RAG V4 Evidence-First (already installed separately by the user). This consolidation does **not** replace its code or re-enable Fabric.

## 1. RAG and NLP are different problems

- **NLP / CamemBERT:** "I moved 230 plants" -> infer action and entities -> editable form. The model works on the *sentence itself*.
- **RAG:** "How many plants were sown by species?" -> *find current authorized facts* -> calculate -> present an evidence-backed answer. The facts live in Excel, MongoDB or approved Markdown files; the LLM should not memorize them.

Retrieval-Augmented Generation (RAG) has three conceptual phases: **retrieve**, **augment with evidence**, **generate/explain**. In SmartTrace the term **hybrid** also means exact structured queries *plus* document/semantic retrieval. A vector similarity search can't reliably calculate a sum, average or distinct delivery-note count; those must be deterministic.

## 2. What each region of the RAG page means

**Poser une question** (`frontend/src/RAGAssistant.jsx`): write a French question. Sends `POST /api/rag/ask` using your JWT. Backend interprets question and picks a data route. It displays a **natural-language summary**, a table (if applicable), any warning and citations.

**Explorer les données**: a controlled query builder for cases where language interpretation is wrong. Loads the permitted catalog from `GET /api/rag/catalog`; employee selects dataset, metric, grouping, filters and pagination; sends `POST /api/rag/explore`. This avoids arbitrary text-to-MongoDB query execution.

**Tableau de résultats**: derived from the calculation engine, not generated by the LLM. If `10 premiers`, it is an explicit paginated subset, not the complete dataset.

**Source et provenance**: current MongoDB (site-restricted), historical Excel (admin-only, non-certified), or internal document (manifest + ACL). They cannot be silently treated as equivalent.

**Précisions et limites**: e.g. missing percentage values, date inference, unit incompatibility, partial result, difference between operational loss ratio and historical `Perte_Totale`.

**Voir les sources et justificatifs**: data-row IDs or approved document excerpts allowing manual verification.

**Détails techniques de la recherche**: reveals the structured query plan for debugging. This is **not** the LLM's hidden thought process. Showing JSON and feature scores to an end user by default would reduce clarity.

## 4. React functions and hooks in `RAGAssistant.jsx`

| Function / hook | Meaning |
|---|---|
| `DataTable({table})` | Displays trusted table cells returned by backend analytics. Does not calculate totals in JSX. |
| `AnswerView({entry})` | Organizes summary, possibly multiple result panels, warnings, data provenance, cited records and expandable diagnostics. |
| `RAGAssistant({token})` | Main page owning two tabs, query input, result history and Data Explorer state. |
| `useEffect` fetch `/api/rag/catalog` | Loads only the datasets and fields visible to the logged-in role. |
| `useMemo(selected)` | Computes selected dataset metadata to populate allowed dropdown values. |
| `useEffect` on `selected` | Resets invalid metric/group/filters when dataset selection changes. |
| `request(path,payload,visibleQuestion,isExplore)` | Authenticated shared HTTP POST; adds a chat entry, handles cancellation and errors. |
| `ask(event)` | Submits a free-text question to `api/rag/ask`. |
| `explore(event,offset)` | Builds the allowlisted explicit query and submits to `api/rag/explore`. |
| `loadMore()` | Requests the next page, using a validated offset; it doesn't fetch all records into the browser. |
| `changeFilter(index,key,value)` | Edits one filter row without mutating other filters. |

## 5. Example: Why one question needs a source-selection step

Question: « Combien de plants ont été semés par espèce ? »

1. `api.ask` authenticates the employee and receives the question.
2. `planner.maybe_plan` selects an operational `seeds_sown` metric, grouped by species.
3. `explorer.explore` checks permissions and queries active records. It might find none.
4. If the role is admin, `source_selection.alternative_for_empty` maps to the **comparable** historical Excel `QteSemis_Rapport` metric.
5. It labels the result *historical, non-certified*, without pretending it represents today's stock.
6. `presentation.present_explore` formats the total by species and provides citations.
7. `AnswerView` shows the employee an understandable table and optional technical method.

The step-4 fallback is **not appropriate for every question**. « Quels lots attendent un contrôle qualité ? » is a **current operational status** question, which historical production rows cannot answer. If MongoDB has no status data, the answer must state that honestly.

## 6. Example: How semantic document RAG works

- Put an approved text document in `backend/rag_documents/` and register its filename, title and allowed roles in `manifest.json`.
- `documents.load_chunks` breaks it into retrievable passages.
- `documents.visible` filters passages by the employee's permissions **before ranking**.
- `lexical_rank` uses matching terms. With `RAG_USE_EMBEDDINGS=1`, `search_documents` adds multilingual embedding similarity, useful when the user paraphrases.
- Optionally enable `RAG_USE_OLLAMA=1` so `llm.synthesize` converts evidenced text into readable French. If no adequate passage is retrieved, it should abstain instead of inventing procedure steps.

Document retrieval is a different skill from financial/production analytics. Evaluate both paths separately: retrieval precision/recall of relevant passages, exact numerical correctness, citation correctness, permission-denial tests, and refusal on unknown information.

## 7. A learning progression for CV and interviews

1. **Deterministic baseline:** embeddings OFF, Ollama OFF; verify datasets, metrics, filters and row-level access control.
2. **Semantic retrieval:** embeddings ON, Ollama OFF; test paraphrased questions against a manually labeled query-to-passage benchmark.
3. **LLM planning:** enable local planner only after evaluating output-schema validation, access-control enforcement, and failures. An LLM-generated *plan* is not an unrestricted DB query.
4. **Grounded generation:** enable local Ollama for explanations of approved passages and measure citation faithfulness. Keep all facts and numeric values under programmatic verification.
5. **Monitoring:** track unsupported intents, failed source selections, query latency, human correction rate and drift in data schemas.
